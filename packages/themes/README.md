# Bundled themes

The free themes that ship with ShopMe, next to Aurora (`packages/theme-default`, handle `aurora`). Merchants add them to their
theme library from Online Store > Themes > "Free ShopMe themes", and can pick one as the starting theme of a new store. This
folder is copied into the Docker image and the desktop app, and is found by the server without configuration
(`THEMES_DIR` overrides it).

```
packages/themes/
  README.md
  previews/                   <handle>-desktop.webp, <handle>-mobile.webp   (generated, see below)
  <handle>/                   one folder per theme; the folder name is the handle
    LICENSE                   MIT
    changelog.json            what changed in each version (same format as Aurora's)
    checksums.json            generated by scripts/theme-checksums.mjs
    layout/ templates/ (templates/customers/) sections/ blocks/ snippets/ assets/ config/ locales/
    demo/                     optional, never installed: catalog.json and images/*.webp of the demo store (see below)
```

A theme folder holds **theme files only** (the format is in [docs/spec/theme-format.md](../../docs/spec/theme-format.md)) plus the
three files above. Nothing else is installed: the installer reads `layout`, `templates`, `sections`, `blocks`, `snippets`,
`config`, `locales` and `assets` and ignores the rest, and a folder without a valid `config/settings_schema.json` (such as
`previews/`) is not a theme.

## Metadata

Everything the gallery shows comes from the first group of `config/settings_schema.json`:

```json
{
  "name": "theme_info",
  "theme_name": "Nocturne",
  "theme_version": "1.0.0",
  "theme_author": "ShopMe contributors",
  "shopme_description": "A dark, high-contrast storefront for electronics and gadgets.",
  "shopme_descriptions": { "fr": "Une boutique sombre et contrastée pour l’électronique et les gadgets." },
  "shopme_tags": ["Tech", "Dark"],
  "shopme_industries": ["electronics"],
  "shopme_catalog_size": "some",
  "shopme_features": ["cart-drawer", "predictive-search"]
}
```

| Key | Required | Meaning |
|---|---|---|
| `theme_name` | yes | Name shown on the card, and name of the theme in the library. |
| `theme_version` | yes | Dotted version (`1.0.0`). Bumping it is what offers "Update theme" to merchants. |
| `theme_author` | yes | `ShopMe contributors` for the bundled themes. |
| `shopme_description` | yes | One or two sentences, in English, shown on the card. |
| `shopme_descriptions` | no | The same text per language (`fr`, ...). The admin picks its own language and falls back to English. |
| `shopme_tags` | yes | A few short English tags ("Fashion", "Food", "Tech", ...). The admin translates the tags it knows (see `apps/admin/src/i18n/en-theme-gallery.ts`, keys `themes.tag.*`) and shows the others as written. |
| `shopme_industries` | yes | Slugs of the trades the theme is made for (`fashion`, `accessories`, `home-decor`, `beauty`, `food-drink`, `electronics`, `art`, `general`): the "Industry" filter of the theme store. |
| `shopme_catalog_size` | yes | `one` (a single product), `few` (up to 20), `some` (20 to 200) or `many` (200 and more): the "Catalog size" filter. |
| `shopme_features` | yes | Slugs of what the theme offers (`predictive-search`, `cart-drawer`, `selling-plans`, `product-filters`, `colour-swatches`, `quick-add`, `sticky-header`, `mega-menu`, `infinite-scroll`, `breadcrumbs`, `back-to-top`, `stock-counter`, `countdown-timer`, `age-verification`, `free-shipping-bar`, `multilingual`): the "Features" filter. |

The theme store shows each of these three with the number of themes it holds. Their labels (EN and FR) are the admin's keys
`themes.industry.<slug>`, `themes.size.<size>` and `themes.feature.<slug>`; a new slug needs its two strings.

## Seed texts (French and other languages)

The texts a theme ships with (hero headline, button labels, section headings, schema defaults) are English. A shop whose
language is French gets them in French at install if the theme provides a map in `locales/fr.json`:

```json
{
  "seed_defaults": {
    "Shop now": "Acheter maintenant",
    "Featured products": "Produits phares"
  }
}
```

At install, every quoted occurrence (`"Shop now"`) of a key in the theme's templates, sections, blocks, section groups and
schema defaults is replaced with its translation; locale files are left alone. It happens only at install (and when an update
creates the new copy for a French shop), so merchant edits and existing installs are never touched. Any language works the
same way (`locales/<language>.json`); a theme without a map for the shop's language is installed as written. Keep each English
text identical wherever it appears, and put the full storefront translations in the locale files as usual.

## Demo catalogue

A theme can ship `demo/catalog.json` (store name, collections, products with titles, descriptions, prices, options and variants, menus,
pages and home page texts, in English and French) and `demo/images/*.webp`. The installer ignores the folder.
`node scripts/theme-previews.mjs <handle>` seeds it into a temporary store so the previews, and the theme store's "View demo", show a
real-looking shop of that theme's trade; themes without a demo are photographed on the coffee demo store. `--qa <dir>` also writes
screenshots of the home page, a collection, a product and the cart drawer at 1440 and 390 px, `--lang fr` does it for a French store.

## Theme kit

Sillage, Foyer and Maroquin are generated: their folders are the output of `scripts/theme-kit` (header, card, product page and
collection variants, shared plumbing, per-theme options). Edit `scripts/theme-kit/themes/<handle>.mjs` or the kit, then run
`node scripts/theme-kit/build.mjs`; do not edit these folders by hand. See [scripts/theme-kit/README.md](../../scripts/theme-kit/README.md).

## Updates

Shops keep the version they installed. When `theme_version` goes up, Online Store > Themes shows "Update available" and creates
a new unpublished copy that carries over the merchant's settings and edits (see section 14 of the theme format). So, with every
release of a theme:

1. bump `theme_version`;
2. add an entry at the top of the theme's `changelog.json` (`version`, `date`, `notes.en` and `notes.fr`, one short line per change);
3. run `node scripts/theme-checksums.mjs <handle>` to refresh `checksums.json`.

## Adding a theme

1. Create `packages/themes/<handle>/` with the theme files, `LICENSE` (MIT), `changelog.json` and the `theme_info` metadata above.
   Write everything yourself: no code, CSS, icons or text from other products.
2. Add `locales/fr.json` with `seed_defaults` if the theme has texts worth translating at install.
3. Run `node scripts/theme-checksums.mjs <handle>`.
4. Build, then run `node scripts/theme-previews.mjs <handle>`: it seeds a demo store, installs the theme, and writes
   `previews/<handle>-desktop.webp` (1440x900) and `previews/<handle>-mobile.webp` (390x844) from the home page.
5. If a tag is new, add `themes.tag.<tag>` (lowercase, hyphens) to the admin's EN and FR strings.
6. Add an entry under "Unreleased" in the CHANGELOG.

The registry (`packages/core/src/services/theme-registry.ts`) discovers the theme on its own: no list to edit.

## Scripts

- `node scripts/theme-previews.mjs [handle...] [--out <dir>]` (after `pnpm build`): previews, as above.
- `node scripts/theme-checksums.mjs [handle...]`: `checksums.json` of every bundled theme, from the history of its folder.
- `node scripts/theme-kit/build.mjs [handle...] [--check]`: regenerates the themes built with the kit.
- `node scripts/theme-kit/demo-images.mjs [handle...]`: converts the demo photos of a kit theme to WebP.
- `node scripts/theme-zip.mjs [handle...] [--out <dir>]`: uploadable zips of the themes (theme files only), for distributing a
  theme or trying it with Online Store > Themes > Upload zip.

The `previews/` folder is served only to signed-in admins (`/admin/api/theme-previews/<file>`).
